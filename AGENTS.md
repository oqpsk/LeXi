# LeXi maintenance

- Keep the product focused on quick dictionary lookup and user-requested text translation. Windows is the current target; macOS is future work.
- Use this repository as the canonical source. Work in a topic branch after the initial import and record changes in CHANGELOG.md.
- Run scripts/Test.ps1 and scripts/Check-Privacy.ps1 before committing. Live provider checks require the user's authorized local subscription and stay out of CI.
- Do not run computer-use or desktop UI automation tests unless the user explicitly requests them. Report build/program validation separately from observed UI behavior.
- Never commit credentials, OAuth codes, private account information, local absolute paths, userdata, query caches, logs, downloaded clients, binaries, or full dictionary data.
- Delegate authentication to the official provider CLI. Do not read or copy its tokens. Do not alter global provider settings.
- Preserve source citations and uncertainty labels. Partial output must remain visibly provisional and must not enter the cache.
- Keep offline lookup functional without online providers. Preserve user settings during updates.
- Keep dictionary and translation caches separate. Preserve case and paragraph boundaries in translations. Never automatically switch models.
- Dictionary lookup may run two explicitly configured models concurrently, followed by the configured Codex sense judge; translation uses only the primary model. Keep model caches and evidence identities separate. Show the first result before merging, retain every original variant, and never upgrade provenance based on model agreement. Uncertain or contradictory senses must remain separate; judge failure must not discard definitions.
- Compare senses within each model as well as across models. Group facets only within the same lexical usage, prefer the most comprehensive original wording, and keep every original definition accessible. Preserve distinct referents, political versus general insults, literal versus figurative usages and parts of speech. Version comparison caches when judgment semantics change.
- Prefer sourced pronunciation over model IPA, label model-only IPA as unverified, and retain pronunciation attribution. Speech is explicitly triggered by the user, defaults to Windows synthesis, and never automatically changes provider. Cloud speech uses separate user-entered API keys encrypted with Windows current-user protection; never reuse or inspect subscription OAuth credentials. Keep audio and keys out of Git and release packages.
- Route words, phrases and text automatically, including translation direction. Do not add query-mode or target-language selectors to the main interface.
- Use vector geometry for UI icons. Keep selected text legible and exclude interactive controls from window dragging; system backdrops must retain an opaque fallback.
- Keep bilingual definitions readable at 20/18 DIP. Treat examples, detailed sources and alternate wording as expandable secondary information. Use English serif italic parts of speech in the warm accent, upright serif spellings and serif examples; omit redundant word-form and bilingual-definition headings; use plain Chinese usage labels and omit neutral boilerplate. Keep model supplementation identified quietly in the source disclosure, with full provenance inside; lack of supporting excerpts must not look like an incorrect-definition verdict. Preserve disclosure state during updates.
- Keep search-row controls aligned with consistent icon and hit-target sizes. Use a compact indeterminate status ring with hover and keyboard-accessible stage details, a completion check and a distinct incomplete-state symbol. Model completion is not whole-query completion: only finalize after merging returns or an explicit terminal exit. Label live counts as previews, distinguish incomplete outcomes, and reject stale updates without inventing percentages or time estimates.
- Keep IPA legible at 20 DIP on the same text baseline as the headword. Place model-only provenance in a smaller adjacent label without removing its uncertainty explanation; allow long headings to wrap.
- Keep query status in the single bottom bar, regeneration visibly styled as a button and online mode as an accessible two-state switch. Keep dictionary management in settings rather than displaying a passive footer count.
- Preserve regional terminology as separate labeled source text and index both variants. Terminology pairs do not verify a generated explanatory definition. Add selected dictionaries without replacing unrelated installed sources.
- Retain original dictionary text and attribution. MOE entries must stay in their original form and must not be supplied as AI rewriting evidence.
- Display recorded word forms outside the generated-definition card. Resolve inflected entries to their lemma even when an exact entry exists; merge recorded online headword forms with local data and cache them for offline use. Completed model answers may supplement missing forms only for the parts of speech they actually define. Keep model morphology identified, never infer suffixes in application code, never upgrade its provenance through model agreement, and retain conflicting proposals without displacing recorded spellings. Preserve legacy cache fallback and isolate late updates from subsequent queries; keep noun and verb uses distinct. Keep mixed-font word-form labels and spellings on one typographic baseline.
- OAuth entry points launch the official client only on an explicit user click. Check status through official commands, display sanitized summaries, never log account identifiers or read credential files. Keep sign-in effects separate from saving application settings.
- Use LeXi / ξ for the public brand. Preserve existing executable, IPC, AppUserModelID and userdata identities for upgrade compatibility. Keep future macOS work in this repository and share the core; do not claim WPF or Windows services run on macOS.
- Avoid unrelated refactors and new runtime dependencies. Do not add global shortcut hooks, selection translation, launchers, account systems or subscription services.
- Use direct Chinese explanations with the result first. Avoid “不是……而是……”, “本质上”, “换句话说”, “总的来说”, “值得注意的是”, “需要注意的是”, “当然”, “其实”, and repetitive conclusions.

- Preserve case in dictionary request and cache identities, with case-insensitive keys confined to the local index. Keep abbreviations, their full expansions, and ordinary homographs distinct in morphology and merging.
- Prioritize known cryptoasset, blockchain, cryptography and information-security meanings without inventing them. Reference briefs are original attributed summaries; keep them visible if generated output omits their cited meaning. New terms must continue to use general coverage rather than word-specific application branches.
- Reject malformed IPA escapes; render sourced and model IPA with consistent delimiters. Etymology remains collapsed, with source excerpts separate from model explanation; do not promote mnemonics or model agreement into historical evidence. Use serif italic examples and visibly interactive “参考资料” disclosures.

- Keep quick-read glosses tied to completed displayed senses, with concise complete-text fallback for legacy/offline data. Never add a separate summary model call or turn truncation into a new definition. Keep preview/partial status explicit. Specialist fallback rows remain until a compatible completed sense cites their evidence; retain the brief in that sense’s reference disclosure. Etymology belongs in a keyboard-accessible headword popover, not a standalone result row.

- Restore completed query views without network or automatic age/settings refresh. Only explicit regeneration replaces saved results. Preserve original model/source provenance across setting changes, separate translation identities, and never replace a good saved view with failed regeneration or streaming previews. Use one pale-pink base color for all pink UI states, with opacity variants for backgrounds and dark text on solid pink fills.
