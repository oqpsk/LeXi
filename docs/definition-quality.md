# 释义质量评估

`quality-check` 验证评估工具和 24 项人工维护的用例清单，不调用任何模型。
`quality-score tests/fixtures/quality-cases.json answers.json` 对已收集的完整模型答案做离线回放。
答案文件格式为 `[ {"id":"genre-cyber","entry":{...AiEntry...}} ]`，不要将私人查询或真实模型输出提交仓库。

自动指标包括：查询身份、中文惯用译名、TL;DR 保留译名、核心义选择、原生领域、缩写全称、双语例句、短释义长度和预期义项覆盖。缺少样本也计为失败。它们不能证明事实正确；语源、含义准确性、例句自然度和误合并仍需人工审读。

每次修改提示词前后，用相同提供方、模型、effort、速度和用例采集完整答案，每项至少三次，记录首条释义时间、总耗时、失败率、自动指标及人工评语。不能将已通过单元测试表述为在线模型质量通过。暂未收集这版的在线 A/B 样本。

提示词现在按安全、输出契约、译名与快读、词义覆盖、形态、语音语源、翻译分组。没有额外摘要或质量审查模型调用。合并仍只选择现有义项，不重写、不裁判事实；不确定的区别保留。

质量基线要同时覆盖普通词、专业词、缩写与大小写、同形异义、中文和变形。新增失败案例进入测试数据，不进入业务代码特判。
